## Two distinct snapshot types; neither grants profitability
**Bor/EBS chain-state snapshots** are crash-consistent backups/recovery input. They reduce RTO when independently verified; cannot certify current canonical state and must never be mounted as a second simultaneous writer. Preserve recovery volume and rollback chain of custody.
**In-memory graph/state snapshots** are immutable records keyed by chainId, blockNumber, blockHash, registryVersion, physical ID, protocol native state and quote inputs. Deduplicate identical reads inside one block, retain bounded topology intelligence only across blocks, invalidate on reorg/head drift and prohibit stale native quotes from promotion. Relevant existing APEX implementation: `SingleFlightStateCache`, `PersistentPoolStateCache`, `SnapshotRef`; actual consumption and TTL must be independently verified. Prefer deterministic immutable graph generations and bounded cache metrics instead of unbounded RAM or greater native node cache by default.
